## Why

单人多 worktree 并行时交接断链: Phase D 把 handoff 写在 feature worktree (分支未合 main), 新会话默认在主 worktree 启动, `scan.py` 仅按 cwd 采集 → 读不到 worktree Y 的最新 handoff, 新会话被引导进错误状态 (2026-06-04 SilkNode cut2-batch1 实地事故)。v1.44.0 核验: 全 collectors 零 `git worktree list` 调用; layer-l TASK-024/025 仅覆盖 cross_owner **创建** worktree, single-owner **进入已存在** worktree 是盲区; **Step 1.17 `handoff_multibranch` 仅扫 `refs/remotes/origin/*`, worktree 分支未 push 时看板同样失明** (sandbox e2e: `tracks_multibranch.exists=False`)。

修复方向 = **纯机械发现, 零 frontmatter schema 变更** (DEC Q1=A): 事故根因是"发现不了"不是"声明不够"; `git worktree list` 给出的 path/branch 是扫描时刻机械真值永不 stale; 加字段会破 E1 `head -8` 自校验窗口并牵连 #137 enforcement + standards §2.3.1, 改动面翻倍。issue 原案三件套中 frontmatter 字段裁掉, 跨树发现 + EnterWorktree 引导保留。

## What Changes

1. **新 collector `handoff_worktrees.py`** (Phase 1.15b, 紧随 1.15; `state-scanner/scripts/collectors/`):
   - `git worktree list --porcelain` 枚举 (path + branch + HEAD); 排除当前树 — **排除比较须双侧 canonical**: porcelain 绝对路径与 project_root 各自 `Path.resolve()` 后比较 (scan.py:220 已 resolve 一侧), 防 symlink cwd 下当前树被当他树卷入产生自指误导 (R1 m-8)。**单 worktree → 整段 no-op** (零行为变化)。
   - **复用机制钉死** (R1 m-7 + R2 N-3): 从 `collect_handoff` 抽出共享 `_resolve_latest(canonical_dir)` helper (单份 H5 pointer→mtime 逻辑, `collect_handoff` 主流程行为不变; `B-M1` stat 缓存随 helper 迁移)。**helper 不直接 emit 软错 — 返回值携带软错信号 (pointer-stale / stat-fail), 由调用方决定发射** (这也是"逐字段不变"的实现前提): 当前树调用方 (collect_handoff) 照旧发射既有信号; 他树调用方对 `handoff_pointer_target_missing` / `handoff_stat_failed` **发且 message 带树前缀** (与 `handoff_canonical_scan_failed` 同口径 — stale pointer 正是 H5 事故形态, 跨树静默会掩盖真问题)。新 collector 对每个他树调用该 helper + 自行 `read_text` + 既有 `parse_handoff_frontmatter` 取 status/track-id/updated-at。**他树不发 #137 `handoff_frontmatter_missing` 软错、不扫他树 `.aria/handoff/`** — 防 errors[] 污染触发 E2 误警 (该软错语义锚定"当前树 latest")。只读发现零写入, 不做 claim/heartbeat (Layer L phase1_gate 职责, 不混)。
   - **当前树数据流** (R1 m-6 + R2 N-4 澄清): 当前树的 resolved latest **消费 Phase 1.15 `collect_handoff` 产出** (循 scan.py:93 `collect_changes_analysis(phase1_git.data)` 前例), scan.py 注册体现 1.15 → 1.15b 依赖顺序。**"不重算"仅指 pointer→mtime 解析不二次执行**; 当前树的**仲裁键**仍按统一规则取 — 对 1.15 产出的 `latest_path` 补一次 `read_text` + `parse_handoff_frontmatter` 取 updated-at (缺/malformed 降级 mtime), **不得**直接拿 `last_modified_iso` (mtime) 当当前树比较键 (防当前树恒 mtime / 他树 updated-at 的混合域偏置)。
   - **跨树仲裁** (含当前树; R1 I-3 钉死): 比较键 = frontmatter `updated-at` (机读 SOT), 缺失/malformed → 降级该 doc mtime。**比较在统一 epoch 域进行**: updated-at 解析为 aware datetime → epoch 秒, 解析须同时兼容 `Z` 与 `+HH:MM` offset 形式且**不依赖 Python 3.11 fromisoformat 行为** (显式 `.replace('Z','+00:00')` 预处理或等价), 解析失败按 malformed 降级 mtime; mtime 侧直接用 epoch 秒 (st_mtime), 不经 ISO 字符串字典序比较。**tie (epoch 相等) 规则** (R2 N-2 补全): 当前树参与并列 → current-tree-wins (`global_latest_elsewhere=null`, 防虚假 advisory 打扰); 两他树并列且均新于当前树 → **path 字典序小者胜** (确定性, 与 others[] 排序键统一)。不引入第三套"最新"定义, 不退回裸 mtime 全局比较 (H5 实证否定)。
   - snapshot **additive** 顶层字段 (不 bump `snapshot_schema_version`):
     ```
     handoff_worktrees: {
       enabled: bool,               # config 开关状态 (R2 N-1, 对齐 issue_scan 禁用先例 issue_scan.py:590)
       enumerated: bool,            # 枚举已尝试且成功 (disabled 时 false 且无 enumeration 软错)
       worktree_count: int,         # 含当前树
       others: [ {path, branch, doc, updated_at, status, track_id, cmp_key_source} ],
       global_latest_elsewhere: null | {path, branch, doc, status, age_hours} }
     ```
     **字段语义** (R1 m-9/m-10 + R2 N-7 钉死): `global_latest_elsewhere` = 跨树仲裁出的全局最新 doc **不论 status** (阶段 2 用 status 字段 gate 触发, 字段本身保持仲裁诚实); `others[].cmp_key_source` = 该条目跨树比较键来源, enum `frontmatter` (用了 updated-at) | `mtime` (降级) — 命名避开 `handoff.latest_source` 的 'mtime' 双语义碰撞; **显式裁定不记录树内 resolution 来源** (pointer|mtime, 即 latest_source 维度): 阶段 2 行为不依赖它, 需要时 additive 后补; legacy doc (无 frontmatter) 缺省值对齐 `handoff_multibranch.py` track dict 约定 — `status='legacy'`, `track_id` filename 派生, `updated_at`=mtime 降级 ISO; `age_hours` 基准与仲裁键一致 (有 updated-at 用 updated-at, 降级 mtime); 文档字段统一命名 `doc` (不用 latest_doc/doc 同物异名); `others[]` 排序键 = path 字典序 (与 tie-break 键统一, 正面声明在 state-snapshot-schema.md 落地)。
2. **阶段 2 advisory 引导** (R1 I-2 裁定: 做成 **handoff awareness mandatory 集成步骤的新增分支**, 非 priority 表规则):
   - 落点 = `references/recommendation-stages.md` §handoff awareness 集成 (阶段 2 推荐生成前 MUST-check) 新增 handoff_worktrees 检查分支; `RECOMMENDATION_RULES.md` 仅加 cross-ref 注 (不进优先级表, 无数值 priority — 触发时序在所有表内规则之前, 与既有 handoff awareness 3-branch 同位)。
   - 触发条件: `global_latest_elsewhere != null && global_latest_elsewhere.status == "active"`。
   - 行为: 警示 + 编号选项 `[1] EnterWorktree 切过去续 track / [2] 留在当前 worktree / [3] 先看该 handoff`; 用户选 [1] 才执行 (DEC Q3=A, advisory-over-hardlock); 非 Claude Code 环境 (无 EnterWorktree 工具) 降级打印 `cd <path>` 指引。
   - `status` 为 `done`/`abandoned`/`legacy` → 仅在列表展示不触发推荐 (`global_latest_elsewhere` 仍如实指向该 doc, 仅阶段 2 advisory 不触发; R2 N-8 防字段级排除误读), 防误引导已收尾/身份不明 track。
3. **降级与上限**: 软错误全走 `errors[]` + exit 10 — `worktree_enumeration_failed` (git 失败 → `enumerated=false`, 阶段 2 不触发) / `worktree_unreachable` (单树跳过, 记 path) / 树内扫描失败复用 `handoff_canonical_scan_failed` 语义 (message 带树前缀)。worktree 数上限 (R1 I-1 钉死): **仿照 `resolve_max_branches_scanned` 的三层模式新建独立 resolver** (非调用既有函数 — 该函数硬连线 `ARIA_HANDOFF_MAX_BRANCHES`/`handoff_multibranch.max_branches`/default 20, 直接复用会得错 default 且 env 串扰), 命名契约: env `ARIA_WORKTREE_MAX_SCANNED` > config `state_scanner.worktree_scan.max_worktrees` > default **8**; int 域 fail-soft 对齐 #71。超限截断 + soft warn。不扫 bare/prunable; detached 树照扫 (branch 记 `(detached)`)。
4. **配置**: `state_scanner.worktree_scan.enabled` 默认 **true** (无多 worktree 时零成本 no-op, 与 1.16/1.17 default-on 一致; issue_scan 的 opt-in 理由是网络开销, 此处不适用); `state_scanner.worktree_scan.max_worktrees` 见上 (同 namespace)。
5. **文档互引**: `references/layer-l-integration.md` §worktree 触发条件加一行 — TASK-024/025 (cross_owner **创建**) 与本机制 (single-owner **进入**) 正交互补; `references/phase-1-collectors.md` 1.15b 行内含反向互引一句 (双向闭环)。
