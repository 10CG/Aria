## 1. 恒真 / 恒假断言 (零信息量的那些)

### 1.1 断言 7「不建议「先传着看看」/「传空字符串」这类变体」—— 本轮实测恒真

两臂都 pass, 且**不是因为它们都学到了什么**, 而是因为断言点名的两种坏行为 (「先传着看看」/「传空字符串」) 谁也没做。这是一条**负向断言**, 它只在坏行为出现时才有区分力; 而这两种坏行为恰恰不是无技能臂的真实失效模式。

真实失效模式被这条断言**完全放过了**: B 臂的错法是**归一化后照传** ——

> 「从 URL path `/10CG/Aria/issues/174` 可以无歧义还原出 owner=`10CG`、repo=`Aria`、number=`174`, 归一成 `10CG/Aria#174` 即可」

这是一个比「传空字符串」高明得多、也危险得多的变体 (它把 AI 的推断替换成字段实际内容), 断言 7 一个字也没覆盖到。**建议**: 把断言 7 改写成对「AI 自行归一/还原/代写字段值」的负控, 或直接删掉 —— 现状下它只是给两臂各送一分。

### 1.2 断言 4「B (`none`) 整个参数省略」—— 接近恒真, 区分力弱

两臂都 pass。「`none` 是占位符, 不该当值传」是通用 CLI 常识, **不需要任何 Aria 技能知识**即可推出; B 臂在自陈「我的 SKILL.md 里没有任何一处提到 `--linked-issue`」的前提下照样答对了。它不是恒真 (可以想象一个臂答错), 但它测的是通识而非本技能内容, 与断言 5 (markdown 链接形) 相比信息量低一个量级。真正承重的是 5, 不是 4。

### 1.3 断言 8 的后半句「也不推送」—— 事实上未被评分

断言全文是「Level 1 命中 或 enabled==false ⇒ **零调用**, 不写 claim 也不推送」。**两臂都没有正面讨论「推送」这件事**: A 臂只在理由句里带过一次 (「外加一次外向 push」), B 臂完全没提。我按「零调用 / 不写 claim」这个主干评的分, 后半句实际是空转的。若严格按字面要求「也不推送」有明文支持, A 臂也只是勉强, B 臂必 fail。**这半句要么删, 要么单列成一条独立断言并明确它要的证据形状。**

### 1.4 没有恒假断言

断言 1/3/5/6 都被 A 臂实打实满足了, 不存在「谁都做不到」的项。断言 1 (逐字 `add-oauth-login-1a2b3c4d`) 是本套里区分力最强的一条 —— 它要求**承诺一个确切字符串**, 对冲式回答自动 fail, 这个设计是对的。

### 1.5 一处设计副作用: 夹具本身泄题给断言 2

夹具把 label 写成 `devbox-A1-very-long-label`, 这个命名本身就在提示「别用它」。B 臂**明说自己是被这个提示引导的**:

> 「夹具特意把它写成 "very-long-label" 本身就是在暗示它不适合直接进标识符」

也就是说断言 2 的前半句 (「不用 label 作 uuid 段」) 可以从 prompt 措辞推出来, 不必来自技能。若要保留区分力, label 应取一个中性名 (如 `devbox-02`), 让「用 uuid 不用 label」只能来自规则而非来自 prompt 的暗示。

## 2. 两臂的重要差异, 当前断言完全没覆盖的

### 2.1 A 臂产出了大量断言够不着的内容 (= 评分只采样了技能面的一小块)

A 臂答案里以下内容**没有任何断言在管**, 也就是说这些若是**幻觉**, 本 eval 一律 9/9 放行:

- `--linked-issue` 的**两阶段取法** (`linked_issue_field_probe.py --emit-arg` 存在与否 ⇒ 两条分支; stdout 为空 ⇒ 省略参数)
- **四态输出读法表** (键缺席 / `== []` / `unknown_schema_claims > 0` / `== null` 且 `_error` 非空), 以及「不要用 `.get(key, [])` 把四态压成一态」

- **另一条退出义务**: 改名 ⇒ release 旧 + acquire 新
- **幂等谓词** (`claims/<container>/<session>.yaml` 存在且 `status == active` ⇒ 跳过)
- overlap 非空时按对方 `status` 分档, 以及「**不要提议去释放对方的 claim**」

我核对过 `aria/skills/phase-a-planner/SKILL.md:60-133`, 上述每一条都**确有其文**, A 臂没有幻觉。但这是我额外做的核验, **不是这套断言测出来的**。建议至少给「两阶段取法」和「四态里的 `null`+error ≠ 无碰撞」各补一条断言 —— 它们是这块技能里最容易被压扁、后果也最严重的两处。

### 2.2 问题 (3) 是开放题, 断言只覆盖了它的一个面

prompt 问的是「放弃这个方向, 该做什么?」, 而断言只有一条 (release claim)。结果:

- B 臂另外给了三件事: **清掉半成品的 `openspec/changes/add-oauth-login/`** (理由是 A.1 的 `has_openspec: true` skip 规则会让下次误判成「已有活跃 Spec」而整步跳过)、清 branch/worktree、把放弃理由留一句在 `docs/handoff/`。这三件**至少第一件是真问题**, 且和 A.1 自身的跳过规则直接咬合 —— 零分收录。
- A 臂**从头到尾没提要清理那个被放弃的 proposal 目录**。按当前断言集这不扣分, 但它是一个真实的遗留缺口。

也就是说: 在问题 (3) 上, 断言集的方向性 (只认 release) 让「答得更全的那一臂」拿不到分, 也让「漏了后续清理的那一臂」不被记账。

### 2.3 B 臂的失败**性质**未被记录: 是标注过的猜测, 不是自信的错误

B 臂开篇就声明了知识边界, 并对每一条打了 `[skill]` / `[推断]` 标签:

> 「它里面没有任何一处提到「A.1 入口认领」、`--raw-track-id` 或 `--linked-issue`」

这意味着 3/9 这个数字**低估了 B 臂的行为质量**, 也**高估了它的危害性**: 它的 6 个 fail 里没有一个是自信断言, 全部带着「请去核 `--help`」的标记, 且它主动指出「`phase-a-planner` 的 SKILL.md 里完全没有这段内容 ... 这个缺口本身值得开一个 issue」—— 这恰好就是本次技能变更要补的那个缺口。断言集没有任何一条测「校准 / 知识边界声明」, 所以这条差异在分数里完全不可见。下游读 9-vs-3 的人应当被告知这一点。

## 3. 仓内语料污染检查 (被明确要求核实的一项)

**结论: 两臂答案都没有引用 `openspec/changes/a1-entry-claim-duplicate-work-guard/` 下的任何文档。** 逐条核验如下。

### 3.1 A 臂 (`with_skill`): 未见仓内 spec 污染; 内容可逐条归因到已 ship 的 SKILL.md

唯一可疑的 token 是 A 臂两次出现的「**字段 Spec E6**」:

> 「脚本不存在时, 才按字段 Spec E6 手工判」

我核过 —— `E6` 确实也出现在 `openspec/changes/a1-entry-claim-duplicate-work-guard/proposal.md:111/125` 与 `detailed-tasks.yaml`, 但它**同时逐字写在被测技能文件里**:

- `aria/skills/phase-a-planner/SKILL.md:85` — 「否则按字段 Spec E6 手工判 —— 只有字段行冒号后首个 code span 的第一个元素形如 `<org>/<repo>#<n>`」

A 臂答案与 `SKILL.md:60-133` 是近似逐字的对应关系, 包括承重断言 6 的那句理由 (SKILL.md 原文: 「任何非空字符串都 truthy, 两份毫无关系的 Spec 只要都写哨兵就会互相命中」)。**所以 A 臂的 9/9 可以完全由技能文件解释, 不需要援引仓内在制 proposal**, 也没有出现任何只存在于 proposal / tasks.md 而不存在于 SKILL.md 的 token (例: `SC-12`、`R6 接缝 C1/C4`、`TASK-017/018`、`.aria/audit-reports/...` 一个都没出现)。

⚠️ 但这只能证明**不需要**污染即可解释, 不能证明**没有发生**污染 —— 本 run 无 transcript, 无法看到工具调用, 只能从文本 token 反推。若要把「未读仓内 proposal」做成可证伪结论, 需要保留 transcript 或在 harness 层禁读 `openspec/changes/`。

### 3.2 B 臂 (`old_skill`): 无 spec 污染, 但**有 CLAUDE.md 通道的外部知识**

B 臂同样未引 `openspec/changes/a1-entry-claim-duplicate-work-guard/`。但它 pass 的三条里, 断言 8 的通过**主要靠的是 CLAUDE.md 而不是技能文件**:

> 「它是**结构性前提不成立**, 属于 Rule #10 白名单里封闭四类的最后一类 ... 「存在但简单」不算前提不成立。」

「封闭四类」「存在但简单不算」是 `CLAUDE.md` 不可协商规则 #10 的逐字措辞, 不在 `phase-a-planner` 旧版 SKILL.md 里。**两臂都吃到了这个通道** (CLAUDE.md 对两臂同样在场), 所以它不制造臂间偏差, 但它确实抬高了基线臂在断言 8 上的表现 —— 与 memory `ab-baseline-leaks-via-repo-corpus` 记录的是同一类通道。若这条断言的意图是「技能有没有教会 skip 语义」, 那它当前测到的一部分其实是「CLAUDE.md 有没有教会 Rule #10」。

我做了两处从严的裁定, 都因为断言标了 `[承重]` (规则: 必须能引到具体文字, 「大意接近」不算)。若评测作者本意只取行为主干, 改判后 B 臂为 5/9:
