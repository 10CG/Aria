## 描述

作为 Aria 2.0 系统 owner,我想要 Aria production deploy 之后 (M4 done) 让系统具备:

1. **看历史 (Replay)**: 任意时点能回看某 dispatch 的完整决策链 (state 转换 + LLM 调用 + human decision + rework cycle)
2. **救故障 (Failure analysis)**: dispatch 失败时,LLM 自动分析失败原因 + 给 owner 智能建议 (retry / abort / 重写 issue)
3. **保规范 (Drift defense)**: AI 写代码不能跑偏 — commit message 必须符合规范 + 实施必须符合 spec
4. **改稿 + 重做 (Review loop)**: 看 PR 后 owner 不只能 approve/reject, 还能 `/aria changes` (改稿) 或 `/aria redo` (重做)
5. **可审计 (Audit log immutable)**: 所有事件 immutable 写入,replay + drift detection + failure analysis 都基于这份事实

以便系统从"M4 能跑通"升级到"M5 能信任 + 能自我管理"。

## 验收标准 (Acceptance Criteria)

per [Brainstorm 2026-05-10](../../../.aria/decisions/2026-05-10-us025-m5-brainstorm.md) 锁定 scope:

### A. Replay framework
- [ ] `aria_layer1/replay.py` 提供 `replay(dispatch_id) -> markdown` 接口
- [ ] Replay output 含: state 转换时间线 + LLM 调用 metadata + human decisions + rework chain + failure_analysis 输出 + drift detection 结果
- [ ] **不重跑 LLM** (deterministic state replay only); LLM stub replay + diff testing 推 M6

### B. Reconciler 深度增强 — Failure analysis + smart retry
- [ ] dispatch 进入 S_FAIL 时, reconciler 跑 LLM 分析 (input: fail_reason + last 5 audit events; output: action + reason + suggested_owner_action)
- [ ] **retry**: 自动 re-dispatch (仅当 fail_reason in {'infrastructure', 'timeout'} + retry_count < 1 + LLM confidence > 0.7)
- [ ] **abort**: 写明确 final reason
- [ ] **notify_owner**: Feishu reject 卡片含 LLM 诊断 + 建议
- [ ] LLM model: glm-4.5-air, fallback glm-5-turbo (per M3 ProviderRouter 链)

### C. Drift defense — Commit lint + Spec diff
- [ ] **Commit lint**: AI 写 commit 后, regex/parser 验证 Conventional Commits + Aria 规范 (type prefix / scope / title ≤ 70 / Closes #N)
- [ ] **Spec diff**: dispatch 完成后, LLM 比较 proposal.md vs PR diff, 输出 compliance_score + deviations
- [ ] score < 70 → Feishu drift 警告卡片
- [ ] daily LLM 自审 / prompt drift / behavior drift 推 M6

### D. Review loop — 双模式 hybrid (changes + redo)
- [ ] Comment 协议扩展: `/aria approve` / `/aria reject:` / `/aria changes:` / `/aria redo:` 4 commands
- [ ] **改稿模式 (`/aria changes`)**: 同 PR force-push, prompt = 原代码 diff + feedback, ~50% LLM cost
- [ ] **重做模式 (`/aria redo`)**: 旧 PR close + 新 PR, prompt = 原 issue + feedback, ~100% LLM cost
- [ ] rework_round cap = 3 (合并 cap, 不区分模式), nomadVar `ARIA_REWORK_MAX_ROUND=3` 可调
- [ ] Feishu 卡片显示当前 round + mode (e.g. "rework round 2/3 — changes mode")
- [ ] abi_compat #4 first-decision-wins 保持: 每 round 创建 NEW dispatch row, 同 row human_decision 一次性写入

### E. 审计日志 immutable / replayable
- [ ] Schema migration v3 → v4: 新表 `dispatch_audit_log` (id / dispatch_id / ts / event_type / payload_json) + INSERT-only triggers
- [ ] 8 event types 完整写入 (state_transition / llm_call / human_decision / rework_cycle / failure_analysis / risk_tier_classified / spec_drift_detected / commit_lint_result)
- [ ] db.py helpers: `append_audit_event` / `query_audit_log`
- [ ] DB triggers 强制 INSERT-only (UPDATE/DELETE → RAISE(ABORT))

### F. Risk-tier — schema dual-write only (algorithm 推 M6)
- [ ] Schema migration: ALTER TABLE dispatches ADD COLUMN risk_tier TEXT (不 RENAME / 不 DROP risk_tier_stub)
- [ ] db.py helper: `get_risk_tier(dispatch_id)` (prefer risk_tier WHERE NOT NULL else fallback risk_tier_stub)
- [ ] M5 写入路径: risk_tier=NULL, risk_tier_stub='always' (M4 行为不变)
- [ ] validate-m5-handoff.py::check_risk_tier_migration_acknowledged 通过

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| D Review loop 是 M5 最大 workpackage (~50-55h, 占 M5 41%), 估计偏差风险大 | Phase A.1 早期 break down 到 ≤8h sub-tasks; 每周 progress review |
| Failure analysis LLM 不稳定 (B 项) → 误 retry / 误 abort | confidence 阈值 0.7 + retry_count < 1 + 仅可恢复 fail_reason 类; LLM 错也最多多 1 次 dispatch |
| Spec diff LLM 可能误判 drift (C 项) | score < 70 仅 Feishu 警告 (不阻塞), owner judge 是否真 drift; 阈值可调 |
| Schema migration v3 → v4 风险 | per `feedback_schema_migration_3_safeguard_pattern` 三重保险 (atomic backup + dry-run on copy + apply on prod with integrity check) |
| Layer 2 二次进入 (D 改稿模式) 与 Layer 2 现有 entrypoint 冲突 | Phase A.1 spec-drafter R1 audit ai-engineer 关注; Layer 2 entrypoint 加 mode='rework-changes' 分支 |
| comment-poll direct transition (G) 引入 race condition | 复用 abi_compat #4 first-decision-wins 守卫; CAS UPDATE 防止重复 transition |
