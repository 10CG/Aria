## Critical (1 条)

### [C1] `casefold` 维度与 `number` 维度双双零覆盖, 且 SC-7 结构上救不回来 — `qa-engineer`

构造两个变异体: `mutC` (strip + 译码全对, **漏最后一步 `.casefold()`**) 与 `mutD` (正确算出 `(basename, number)`, **比较键只用 basename**)。

```
== mutC_no_casefold ==  ALL SC GREEN (17 条 SC / 43 子用例零发红)
   probe: ('10CG/Aria-Plugin#122', '10CG/aria-plugin#122', 期望 True, 实得 False)
== mutD_number_ignored ==  ALL SC GREEN
   probe: ('aria-plugin#122', 'aria-plugin#7', 期望 False, 实得 True)
```

**并已证明未来的 fixture 也救不回来**: 把语料从 8 元扩到 20 元 (混入多个大小写变体 + 多个同 repo 不同号), 两个变异体在 SC-7 三性质上**仍 0 违例** —— 因为「忽略某个维度」产生的仍是**合法等价关系** (只是分桶分错), 三性质检查区分不了「实现自洽」与「分组正确」。**这与 R1′/C1 是同一条逻辑, 对第二、第三个维度同样成立, 且不随语料规模改变。**

**后果**: D8(i) 明令授权的三条重写之一 (`casefold()`) 可以被整个丢弃而全套验证永不报警; `number` 相等这个规则 5 用「**且**」强调的必要条件同样可丢弃 —— 一旦丢弃, 机制退化为「同 repo 任意 issue 互相冒充」, advisory 噪音 100%, **比修复前的静默漏报更破坏可用性**。

## 结论与建议

**不建议直接跑 R3′-fix → R3′ 循环。** 理由不是数字, 是成分: 本轮净降 3 条 major 的代价是「修 12 条、造 10 条」。三席中有两席 (tech-lead / code-reviewer) 各自独立给出了同向建议。

**缺陷分三类, 只有第三类适合用「再审一轮」解决**:

| 类 | 本轮实例 | 为什么加轮无效 / 有效 |
|---|---|---|
| **1. 机械同步缺失** | 行号失效 · 计数 stale · SC 枚举漏 · 自指语料漂 | 466 行文档有 ~15 个手工同步点。**加轮只能发现, 不能防止**; 下一轮 fix 会再造一批 ⇒ **要机械检查器, 不要审计席位** |
| **2. 全称句自我证伪** | D8「任意两个」· rule6_note「三要素齐备」· SC-10「其余全部」· 上轮的「结构上不可能」 | 是**写作习惯**, 不是知识缺口。**一次定向 sweep 可清完**, 逐轮碰运气抓不干净 |
| **3. 覆盖维度盲区** | strip 第三点 (R1′) · `#` 方向 (R1′) · `/` 方向 · casefold · number | **真实且高价值**, 但每轮只挖出一两个维度。**应一次穷举**: 比较键的维度是有限集, 逐维度建变异体、要求每维有 killing SC |

2. **给 Spec 写机械一致性检查器** —— 仿 artifact 的漂移守卫, 检查计数一致 / SC 枚举同步 / artifact 行号有效。**把第 1 类从「靠人盯」变成「靠红」。**
3. **对全称量词做一次定向 sweep** —— grep「任意 / 全部 / 唯一 / 结构上不可能 / 均」逐条检验。**第 2 类。**
