**helper 最终写法** (规范性, spec 里写死并注明不得等价改写):

```bash
_sg_line_match() {
  local _re="$1" _s="$2" _l
  while IFS= read -r _l || [[ -n "$_l" ]]; do
    [[ "$_l" =~ $_re ]] && return 0
  done <<< "$_s"
  return 1
}
```

要点四条: (1) `|| [[ -n "$_l" ]]` 处理无尾换行的最后一行; (2) `IFS=` 保留行首尾空白; (3) `-r` 不吃反斜杠 (13 条判据里有 `\|` `\$` `\b`); (4) 正则**不加引号**代入 `=~`, 加引号会退化为字面匹配。13 处调用形如 `if _sg_line_match <原正则文本> "$seg"; then`, **正则一个字节不动**。

### 最终写法 (规范性)

```bash
nl=$'\n'
BLOCK_KW_RE='(^|'"$nl"'|;|&&|\|\||\||&|do|then|else|elif|in)[[:space:]]*(for|while|until|if|case|select)\b'
```

选型理由: 正则主体用**单引号** ⇒ `\|` `\b` 无转义层, 只把换行经 `"$nl"` 拼进去。我同时实测了「先存 `nl` 再整体用双引号」的写法 (需把 `\|` 写成 `\\|`), 两者 `[[ "$W3" == "$W1" ]]` 判定**产出字节相同的正则串** —— 选单引号版纯粹因为它少一层转义, 少一层就少一种写错的读法。

### 正例 / 负例实测 (`a1_newline.sh` + `a1_pick.sh`, 全部实跑)

| 方向 | 探针 | 正确写法 | `(^|\n)` | 裸 `^` |
|------|------|----------|----------|--------|
| **正例 (漏)** | `$'cd /tmp\nfor f in a b; do …; done >/dev/null'` | **MATCH** | no-match | no-match |
| **负例 (多)** | `run for` / `xnfor` / `n for` / `green if x` | **全部 no** | **全部 MATCH** | 全部 no |
| 控制 | `ls; for f in a; do …; done` (同行 `;` 之后) | MATCH | MATCH | MATCH |

即 `(^|\n)` **既漏又多**: ERE 里 `\n` 是字母 n, 既丢掉真换行位置, 又把「以 n 结尾的词 + 关键字」误当命令位置。

**从 markdown 反向抽出来重跑** (`a1_rt.sh`, 按 `> ` 前缀剥离后直接执行): 5 条断言全中 —— `newline-for=false` / `echo run for=true` / `xnfor=true` / 同行 `for=false` / `echo for=true`。
