## High-Priority Findings (R2 should fix)

### **BA-2**: schema_migrate executescript + BEGIN IMMEDIATE 失效 (atomicity 风险)

- Python sqlite3 `executescript()` 自动 issue COMMIT,voids prior `BEGIN IMMEDIATE` → migration 003 的 7 ALTER + 2 CREATE 不是 collectively atomic
- Mitigation: 用 individual `conn.execute()` per ALTER/CREATE statement (不用 executescript)

### **BA-4 + AI-10 (重叠)**: reconciler CAS 可能覆盖 committed approve

- Race scenario: list_stuck_s7 取 row → comment_poll commit `human_decision='approve'` → reconciler CAS 仍成功 (state 还是 S7) → S_FAIL(human_timeout) 写入,但 human_decision='approve' 已存 → DB 自相矛盾
- Fix: cas_mark_failed_stuck SQL 加 `AND human_decision IS NULL` 条件

### **QA-1**: T-acceptance D.1 test 用 manual UPDATE 旁路真实 state-machine commit

- _handle_s7_human_gate 返回 (state, payload) tuple,test 不调用真实 caller (hermes tick handler),改用 `UPDATE dispatches SET state='S9_CLOSE'` 模拟。caller-side commit logic 无 Tier-1 测试覆盖
- Fix: D.1 test 调真实 transition dispatcher,或 separate test 验证 caller commit + 文档化解耦

### **QA-2**: IntegrityError 后 human_decision 留 NULL 但 decision_made 标 'decided' → 死循环风险

- update_human_decision 抛 IntegrityError 时 UPDATE 已 rollback (human_decision 仍 NULL);但 process_dispatch catch 里仍设 `decision_made = decision.kind` + `break` → cursor 推进,**但下次 tick first-decision-wins guard (`human_decision IS NULL`) 不触发** (因为 NULL),会重新 process 同 dispatch
- Fix: catch IntegrityError 后 re-read DB 验证 — 若 concurrent write succeeded → set decision_made;若仍 NULL → log WARNING + 不 set decision_made

### **AI-3**: fetch error 时 cursor 不前进 → transient 故障下 polling 卡住

- comment_poll.process_dispatch fetch_new_comments 抛 RuntimeError/TimeoutError → 仅 log + return None,**未推进 last_polled** → 下次 tick 重试同 PR 同评论,直到 transient 故障消退
- Fix: 加 fetch error 计数 + 阈值 (e.g. 20 次连续失败标 dispatch 'polling_stuck' → reconciler 兜底)
