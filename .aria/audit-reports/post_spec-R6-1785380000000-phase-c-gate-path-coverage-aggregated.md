## Critical (2 条)

### C-1 — 值位互斥的块归属计算未成文 ⇒ C1 原病**第三次**复发

- **位置**: `proposal.md:71` (D12 第 (2) 段 (b))
- **问题**: 排除条件写「缩进 **>** 该键行缩进」。YAML 合法的**同缩进块序列** (`    paths:` + `    - '**.js'`, 序列项缩进 = 4, 不满足 `> 4`) ⇒ **不被排除** ⇒ 落回第 (4) 段: 剥 `- ` → 剥引号 → `**.js` → 首字符 `*` ⇒ 判 alias ⇒ covered ⇒ **恒 wait**。与 R5 C1 的失败链**逐字相同**, 只是入口从「剥引号顺序」换成了「缩进比较符」。
- **同源第二缺口**: 第 (1) 段为 `on:` 区间**显式**写了「空行与纯注释行跳过: 既不参与判定, 也不终止区间」, 第 (2)(b) **无同款子句** ⇒ paths 列表中间的空行 / 列 0 注释按字面终止 paths 块, 其后的序列项不再被排除 ⇒ 同上。
- **双向分叉**: 若实现者的 **paths 列表解析器**也用「缩进 >」找列表项, 同缩进形态下 paths 解析成**空列表** ⇒ 零贡献 ⇒ **假 not_applicable (放行)**。**同一输入, 两个实现方向的错误指向相反** (一个恒 wait, 一个误放行)。
- **复发链 (同一条失败链的第三个入口)**:

  | 轮次 | 入口 | 结果 |
  |---|---|---|
  | L 的 R4 (原发现) | 子串读法 `'*' in line` | 4 份语料命中 3 份 ⇒ 恒 wait |
  | **A1** | 剥引号排在首字符判定前 | `'**.js'` → `**.js` ⇒ 恒 wait |
  | **A2** | 缩进比较符 `>` 排不掉同缩进序列项 | 同上 ⇒ 恒 wait |

- **修法方向** (与危害「排除域算小了」一致): 在 (2)(b) 就地写死序列项归属 (`- ` 开头且缩进 **≥** 键行缩进亦属值域) + 块终点 (首个缩进 ≤ 键行缩进**且不以 `- ` 开头**的非空非注释行) + 空行/注释不终止 (一字不差重述, 不靠「参见 (1)」)。SC-30 增负控 (x)(xi)。

### C-2 — 值位互斥无条件排除 ⇒ 真 alias 被当 pattern ⇒ **本 Spec 迄今第一个 fail-OPEN**

- **位置**: `:71` (排除规则) / `:73` (理据) / `:101` (glob matcher fail 方向) / 对照 `:42` (D2)
- **问题**: (2) 规定「被排除的行**不做任何构造级判定**」。于是两种**真 YAML 构造**失去唯一检出通道:
  - `paths: *common_paths` — 键是 `paths` ⇒ (a) 排除。手写 parser 拿到的值既非 block list 亦非 flow list (`:62` 只建模两形) ⇒ 落未定义行为 ⇒ 零贡献 ⇒ **not_applicable ⇒ 闸门在 CI 本该拦它时放行**。
  - `- *p` (paths 列表项是 alias) — (b) 排除 ⇒ 字面 `*p` 当 glob。**`*` 是本 Spec 已建模的 glob 字符** (`:101` 把未建模限定为「字符类 `[abc]` / 否定 `!` / 其他」), 故**不落**「未建模 → 判匹配 → covered」的安全兜底 ⇒ 走真实匹配 ⇒ 几乎必然不命中 ⇒ 同上。
  - **对照**: 同位置的 `!` 有救 (`:73` 划给 glob matcher, matcher 对 `!` 判匹配 → covered)。**唯独 `*` 两头落空** — D12 不判它 (被排除), matcher 不兜它 (已建模)。
- **与 D2 正面冲突**: `:42` 的核心原则是「任何不确定, gate 行为一律退回现状」「绝不把『解析不了』当『无覆盖』」。`:73` **自己承认**这里确实不可靠区分, 却把它解到 not_applicable 一侧。**A1 在这一点上是 fail-CLOSED (恒 wait, 难受但安全), A2 把它翻成了 fail-OPEN。**
- **⚠️ 实跑推翻了主控在 A2 写的承重断言**: A2 `:73` 写「glob 的 `*`/`!` 与 YAML 的 `*`/`&`/`!` 在同一位置的字符上不可靠区分…**唯一稳健的区分是按位置排除**」。PyYAML 6.0 实跑 (席位提出 + 主控复验):

  ```
  裸  - **.js        → ScannerError: while scanning an alias
  引号 - '**.js'      → 解析成功 {'paths': ['**.js']}
  ```

  ⇒ **YAML 层面, 值位上裸的 `*` 开头 token 必定是 alias, glob pattern 必定带引号。**「唯一稳健」是过强断言 — 存在「**位置 ∧ 形态**」判据既消灭 C1 又不放过 alias。
- **修法方向** (与危害「排除过头 ⇒ 漏检真构造 ⇒ 误放行」一致):
  1. 排除条件由「位置」改「**位置 ∧ 形态**」: 值域内**带成对引号者**判 pattern (排除); **裸 token 且首字符 `*`/`&`/`!` 者仍判构造级** (不排除);
  2. 独立兜底 (即使不采纳 1 也必须有): 「`paths:`/`paths-ignore:` 的值**不是** block list / flow list 两形之一 (含同行标量 / alias / 空值) ⇒ 该 workflow 记构造级不确定 → covered」, 并入 6b 成因;
  3. SC-30 增正控 (xii) `paths: *common_paths` / (xiii) `- *p`。
