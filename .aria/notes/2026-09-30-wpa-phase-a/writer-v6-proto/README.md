# writer-v6-proto: 原型、坏实现、时档与自检脚本 (归档)

`openspec/changes/secret-net-l3-and-bypass-paths/proposal.md` 在 post_spec 之后做定点修补的过程中, 在会话实验目录里做的「完整目标态原型 + 坏实现变体 + 时档度量 + 文本 / 计数自检」的**重建脚本、复跑计划与汇总**。本目录是前一版归档 (`writer-v5-proto`) 的超集: 沿用未改的脚本, 更新有改的脚本, 补上本轮新增的脚本与计划。只归档脚本、计划表与汇总文本; 各树副本、bash 3.2 构建目录与会话日志不入仓。

## 先读这三条

1. **原型不是实现**: 用脚本对基线 (aria `268da8f`、standards `2bc1c4c`) 做文本替换生成, 只证明 proposal 的设计可达, 并给出「哪个坏实现会让哪几行转红」。真实现者拿到的只有 Spec 散文, 不应照抄原型。
2. **脚本里的绝对路径**指向当次会话的实验目录 (`EXP` 变量, 形如 `/tmp/claude-…/scratchpad/exp/writer-v6`)。重跑前把它们改成你自己的实验目录: 先把 aria 与 standards 复制到 `<EXP>/base/` 下并删去其中的 `.git` 文件 (子模块 gitfile); 取得真 bash 3.2 (方法见 `baseline-evidence.md`「取得真 bash 3.2」) 并以 `WPA_BASH32=<路径>` 传给探针; 把上一版的三份文件 (git `6efb9b2` 下 `openspec/changes/secret-net-l3-and-bypass-paths/` 的 `proposal.md` / `baseline_probe.py` / `baseline-evidence.md`) 复制成 `<EXP>/spec/proposal.v5.md`、`baseline_probe.v5.py`、`baseline-evidence.v5.md`, 它们是 `apply_edits_v6.py` 与 `patch_probe_v6.py` 的输入。簇 Y 的 git 腿需要一个带 `af87cae` 历史的 aria 副本: `run_gitcopy_suite.sh` 用本地 `git clone` 取得 (只读源)。回归基准 (`build_mut_summary6.py` 的 `WPA_PREV_CAMPAIGN`) 是上一版终跑的 `mut/final5/` 目录。
3. **Rule #7**: 本目录的文件不含凭据形状字面量 (补丁脚本只处理 hook 里的正则; 凭据形状的值与键名在脚本里运行时拼装, 不打印)。`scan_all.py` 把全部文件当 Bash 输出与 Read 结果各扫一遍, 对基线与目标原型两个 `secret-scan.sh` 都应静默。

## 脚本

- **补丁 (生成目标态原型与坏实现)**: `patch_l3.py` (secret-scan) / `patch_l1.py` (secret-guard) / `patch_hooks_json.py` (hooks.json 的 `PostToolUseFailure` 注册), 默认变体 `v6` = 目标态, `--variant NAME[:ARG]` = 坏实现 (文件头的列表给出每个变体对应的 SC 行); `patch_docs.py` (SOT、README、CHANGELOG、两个 hook 的头注释; `--bad` / `--bad-sot` / `--bad-layer` / `--no-scope` / `--hdr-*` / `--cl-drop=<标记词>` / `--drop56=<关键词>` / `--readme-drop=<关键词>` / `--sot51-nofail` 是文档类坏实现); `patch_tests.py` (两个测试套件的同步改动, 含 guard 套件头注释计数随新增的族探针同步); `build_full.sh <绝对路径> 64` 组装完整目标态树 (目标路径必须是绝对路径; 顺序: 补丁 hook → hooks.json → 测试套件 → 文档)。
- **文本与探针**: `patch_probe_v6.py` 由上一版探针逐处带断言地改出本版探针; `apply_edits_v6.py` 把 `proposal_edits/edits_v6_{a,b,c,d}.py` 的全部编辑按顺序施加到上一版 proposal 上 (锚点缺失或不唯一即停并列出全部失败项; 数字占位符 `@NAME@` 取自 `out/numbers.json`, 由 `mk_numbers6.py` 从原始时档 / 探针输出解析, 不手填)。
- **复跑**: `runprobe.sh <label> <树根> <spec 目录> <b32: 0|1> [WPA_ONLY]` 跑探针 (先快照 spec 目录; `WPA_REQUIRE_ALL_PASS=1` 打开验收模式); `final_runs6.sh stage1|stage2` 是定稿证据的两段复跑 (stage1: A / B / N 基线; stage2: T / TN / C); `mk_evidence6.py` 由 stage1 的 stdout 组装 `baseline-evidence.md` 并断言内嵌块与 stdout 逐字节一致、基线形态成立。
- **变异**: `plans_v6/*.tsv` = 本版计划 (L3 / L1 / hooks.json 三份), `plans_v5/` `plans_v4/` `plans_v3/` = 前几版计划 (每行: 标签 / 种类 `l3|l1|hj` / 变体 / SC 列表 / 行列表), 由 `mkplans6.py` 写出 (本版) 或原样沿用; `mutbatch.py <计划> --tree <树> --spec <spec>` 逐个生成坏实现并只跑指定的行; `run_final_campaign6.sh [jobs] [阶段…]` 依次跑 v6 / doc / v5 / v4 / v3 各批 (`docvariants6.py` 是文档类坏实现); `build_mut_summary6.py` 汇总为 `mut_summary_v6.txt` (转红 0 行的坏实现逐个点名为等价变异或时档类并写明理由, `equiv_reasons6.py`; 前几版转红过的行必须仍然转红 —— 基准是上一版终跑的同名计划同名标签 —— 否则脚本以 1 退出); `coverage_check6.py` 核对「相对上一版新增或改写的探针行都至少被一个坏实现转红」; `validate_plans.py` 核对计划里的变体都被补丁脚本认得。
- **时档与成本**: `timing.py <基线 hook 目录> <目标 hook 目录> [档位] [--pairs N …] [--judge]` 同一次运行内交错 A/B, 记整进程 CPU 时间 (user+sys, 含全部子进程) 的最小值之比与墙钟, 并对 (f) / (f-hit) / (g) / (h) 用注入标记的副本做一次不计时的活性检查; 档位 `f f0 fhit g gmax h i i3 w1`; `--judge` 按 W14 的上界逐档给出 PASS / FAIL 并以退出码表示; `run_timing_good6.sh` 跑目标原型, `run_timing_variants6.sh` 对每个坏实现跑它该被抓到的那一档。簇 W 的设计实验: `w_scan.py` (取值代码在长单行形态上的整进程 CPU)、`ratio_try.py` (目标 / 基线 CPU 比随尺寸的变化)、`pat_cost.py` (kv pattern 的 `grep -oE` / `sed -E` 逐进程 CPU)。`cap_lin.py` 对探针 SC-34 两张成员表 (23 个) 逐个求「仍检出的最小整秒 CPU 上限」, `member_matrix.py` 对每个取值类坏实现求它失败的成员, `scale_try.py` / `stage_cost.py` / `bad_cost500.sh` 量单形态的整进程 CPU 随尺寸的变化与各阶段占比 (`export` 之后空白串成员为什么取 100 KB)。`run_gitcopy_suite.sh <baseline|proto>` 在带 git 历史的 aria 副本上跑两个既有套件 (测试内 SC-8 五档、SC-9a)。`occ_cost.py` 量命令长度 × 出现点对扩展命中路径 CPU 的影响。
- **自检**: `ere_battery.py` (6 个新 pattern 在对抗单行上的缩放)、`ere_claims.py` (W2 线性段引用的 `grep -oE` 秒数)、`fuzz_value_of.py` (取值 / 去空白代码对 17 个 tag 的真实 span 做差分)、`diff_ext_builtin.py` / `fuzz_ext_builtin.py` (扩展条目与内建 `app.ini` 行的差分, 手写形态与随机形态)、`readface_check.py` (SC-18 的 32 条路径各只命中一个基线备选)、`refs_check.py` (Impact 的关闭关键字检查三态实跑)、`scan_all.py` (Rule #7 自扫)、`check_counts.py` (proposal 各 SC 条目声称的 `×N` 与 stdout 逐 SC 对账)、`xref_check.py` (proposal 引用的行号与探针输出对账)、`format_lint.py` (LF / 无制表 / 无带圈数字 / 无 emoji / 无 AI 署名 / 无裸 issue 号 / 正文无版本与审计叙事 / Status 行)、`iso_test.sh` (探针的逐行异常隔离: 一个 hook 调用超时只让该行为 `no`, 验收模式 exit 4)、`l1try.py` / `emptyroot_try.py` / `fail_try.py` (单条命令或信封的退出码直查; `cmds_*.txt` 是本轮设计新行时用的候选命令表)。
- **汇总**: `mut_summary_v6.txt` (每个坏实现转红的行数与行名, 前几版坏实现的回归结果, 等价变异的理由)、`timing_summary_v6.txt` (时档原始输出汇编)、`gitcopy_summary_v6.txt` (簇 Y 的 git 腿)。`../logs/` (交付目录里的 `logs/`) 放定稿证据运行的 stdout / rc / stderr (`final_A` `final_B` `final_N` `final_T` `final_TN` `final_C`)、各脚本输出、`numbers.json`、`campaign.log`。
