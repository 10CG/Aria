timing_summary -- W14 time tiers on the v3 target prototype and on the bad implementations of the tiers (proposal W14 item 5, SC-30)

Method (proto/timing.py): baseline hook (aria 268da8f) and target hook run INTERLEAVED (A/B/A/B...) on the same input on the same host; per run the CPU time (user+sys, via RUSAGE_CHILDREN
deltas, i.e. the whole process tree of the hook) and the wall time are recorded; the statistic per hook is the minimum over N interleaved runs (N = 5 pairs for the target, 3 for the bad
implementations), the verdict statistic is the CPU ratio target / baseline.  Wall time and load average are recorded, never judged.  f / f0 / g / h / i are the W14 tiers; w1 (a Read result
through the L3 hook; the baseline hook does not extract file.content and exits early) is informational for W1's performance sentence.  The `live` / `live-calls` columns are the liveness
assertions: `live-calls=ok(...)` = the set of instrumented functions called in one untimed run of the instrumented target equals the expected set (f: the extension entry is called;
g / h1: the variable-expansion pass is called; h2: nothing is called because a built-in blocks first); `live=(a, b)` = the L3 hook alerted on the dense input in the baseline / target run.
Host: Linux 6.17.9-1-pve, 4 cores, shared (other tenants); the timing runs started when the 1-minute load average had fallen below 1.5.  Numbers move with the host; only ratios are judged.
Thresholds (W14 item 2): (f) / (f0) <= 1.5 x max(baseline, 100 ms); (h) <= 1.5; (i) <= 2.0; (g) <= 2.5.
