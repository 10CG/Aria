timing_summary -- W14 time tiers on the v4 target prototype and on the bad implementations of the tiers (proposal W14 item 5, SC-30)

Method (proto/timing.py): baseline hook (aria 268da8f) and target hook run INTERLEAVED (A/B/A/B...) on the same input on the same host; per run the CPU time (user+sys, via RUSAGE_CHILDREN
deltas, i.e. the whole process tree of the hook) and the wall time are recorded; the statistic per hook is the MINIMUM over N interleaved runs, the verdict statistic is the CPU ratio
target / baseline.  Wall time and load average are recorded, never judged.  f / f0 / g (= W14 (g-a)) / gmax (= (g-b)) / h / i are the W14 tiers; w1 (a Read result through the L3 hook; the baseline hook
does not extract file.content and exits early) is informational for W1's performance sentence.  The `live` / `live-calls` columns are the liveness assertions: `live-calls=ok(...)` = the set of
instrumented functions called in one untimed run of the instrumented target equals the expected set (f: the extension entry is called; g / h1: the variable-expansion pass is called; h2: nothing is
called because a built-in blocks first); `live=(a, b)` = the L3 hook alerted on the dense input in the baseline / target run.  timing.py prints ratios and liveness only: the verdict is read against the bounds.
Host: Linux 6.17.9-1-pve, 4 cores, shared (other tenants); 1-minute load average 1.5-5 during these runs.  Numbers move with the host; only ratios are judged.
Thresholds (W14 item 2): (f) / (f0) <= 1.5 x max(baseline, 100 ms); (h) <= 1.5; (i) <= 2.0; (g) <= 2.5.
Reading of the good-prototype rows below (15-pair run for f / f0, 5-pair run for the rest): (f) Bash 0.072 s and Read 0.067 s <= 0.15 s; (f0) 1.23 / 1.15 (0.058 s / 0.048 s <= 0.15 s); (g-a) 1.39 and (g-b) 2.03 <= 2.5; (h2) 1.25 <= 1.5 with live-calls=ok();
(i) 1.31 and 1.16 <= 2.0.  h1 (all allowed, 2.33) is not a judged tier (see W14 / Impact: 'the denser the references the closer to 2x').  Bad implementations: every one exceeds its bound or fails its liveness check.
