### 实测驳回: A-2 的「死条目 `&`」不成立

审计席的理由是「裸 `&` 已被后台记号行完全吸收, 位置表里的 `&` 是冗余」。**该推理漏了后台记号行自己的排除清单**:

- 后台记号行判降级的是**裸 `&`**, 显式排除 `&&` / `&>` / `>&` / `\|&`
- 而 `cat x |& for f in a; do …; done` **语法合法** (`bash -n` 实测通过; `|& while` / `|& time` 同)
- 该形态下 `\|&` 不触发后台记号; 紧邻 `[[:space:]]*for` 的位置 token 是 **`&`**, 不是 `\|` (`\|` 后面跟的是 `&`, 不是空白)
- ⇒ 删 `&` ⇒ `\|& for …` 不再降级 ⇒ 循环体被切碎 = **覆盖回归**

**副产品**: 保留 `&` 后, 清单「删一 (`in`) 加一 (`!`)」仍是 **12 类**, 故 §What.1 与 Task 1.1(c) 的「其余 10 类」**无需改动** —— tech-lead 估的「要连带动两处计数」这一代价随之归零, 采纳 A-2 的成本比清单里写的低。

**教训 (已入 memory 候选)**: 「X 已被 Y 吸收 / X 是冗余」这类**删除型**建议, 必须先枚举 Y 的**排除项**再下结论 —— 排除项就是 X 仍然承载的那部分。本 cycle「勘正引入新错」第六次, 但这次是**动手前**被机械核实拦下的第一次。
