# 返修单: TASK-002 (主控独立复现发现的缺陷) + 你报告第 5 节的裁定

## 缺陷 (必须修, 修好前不提交)

**现象**: 主控从 `/home/dev/Aria` 用相对路径跑 `HOME=<私有目录> bash aria/hooks/tests/secret-guard.test.sh`, 得 `PASS: 603 / 780`、`FAIL: 177 / 780`, 而不是你报告的 665 / 115。多出的 62 条全是新增守卫类 (rg 25 / ag 21 / kl 16), 失败信息全是 `got 127`, 例如 `{Bash chmod 600 /etc/forgejo/app.ini: want exit 0, got 127}`。scan 套件两种调用方式结果相同 (78 / 44)。

**根因** (主控已核对源码): 套件按 `HOOK="$(dirname "$0")/../secret-guard.sh"` 取 hook (`secret-guard.test.sh:18` 一带), 相对路径调用时 `$HOOK` 就是相对路径; 新增的 `wpa_rc` / `wpa_err` 先 `cd "$wpa_cwd"` (`$wpa_tmp/cwd`) 再执行 `"$WPA_HOOK"`, 相对路径失效 ⇒ `env` 退 127。你用绝对路径调用, 所以没碰到。

**为什么必须修**: 探针就是用相对路径跑套件的 —— `baseline_probe.py:2034-2043` 在副本根目录下执行 `["bash", "hooks/tests/secret-guard.test.sh"]` (bash 3.2 腿同样)。不修的话, TASK-010 验收时探针的零回归行必然撞上它; 而且现在的 115 条 bf 在相对调用下「红」的原因是 127, 不是基线 hook 的行为, 这样的红不能证明测试有效。

**修法要求**:

1. 在新增块里把 hook 路径 (以及其它在 `cd` 之后还会用到的相对路径) 一次性解析成绝对路径。**同类全查** (两个套件的全部新增 helper): 凡是先 `cd` 或在子 shell 里换目录之后再引用 `$0` / `$HOOK` / `dirname "$0"` 派生路径的地方都要处理; 也包括 `wpa_hook_copy` 一类生成 hook 副本的 helper。既有用例 (非 `wpa_` 前缀) 不动。
2. 修完后在**三种调用方式**下各跑一次两个套件 (同一时刻只跑一个):
   - (a) 绝对路径: `bash /home/dev/Aria/aria/hooks/tests/<套件>`;
   - (b) 从 `/home/dev/Aria` 相对: `bash aria/hooks/tests/<套件>`;
   - (c) 探针的形态: 在 `/home/dev/Aria/aria` 下 `bash hooks/tests/<套件>`。
   三种方式的 `PASS / FAIL` 必须相同, 失败集合必须恰好等于 bf 集合, 且全部失败信息里 `got 127` 出现 0 次。HOME 仍指向私有目录。
3. 顺带做一条机械自检, 并在报告里贴出结果: 统计每种调用方式下失败信息里 `got 127` 的次数。
